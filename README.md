# Лабораторная работа 1 — Вариант 3: RGB ↔ XYZ ↔ CIELAB

Веб-приложение для взаимного преобразования цветовых моделей **RGB ↔ XYZ ↔ CIELAB**.
Вся математика реализована вручную, без библиотек конвертации. Архитектура — **MVVM** на
нативных ES-модулях (без сборщиков и внешних зависимостей).

## Возможности

- Три способа ввода для каждой модели: точное значение, ползунок, палитра (плюс общая палитра сверху).
- Автоматический пересчет всех моделей при изменении любой компоненты.
- Предупреждения: выход значения за диапазон ввода и выход цвета за охват sRGB
  (с указанием стратегии — Clipping или Scaling).
- Источники света: **D65** (sRGB), **D50** (полиграфия), **E** (равноэнергетический).
- Смена источника света не меняет цвет на экране: пересчет выполняется от текущего RGB.
- Стратегии выхода из охвата: **Clipping** (обрезание компонент) и **Scaling** (пропорциональное сжатие).
- Встроенная панель самопроверки на странице + канонические тесты в `tests/`.

## Архитектура (MVVM)

```
index.html                  — разметка
styles/main.css             — стили
src/
  model/
    colorMath.js            — чистая математика преобразований (без DOM)
    selfCheck.js            — самопроверка для панели на странице
  view/
    colorView.js            — поиск элементов, слушатели (bind-методы), render(snapshot)
  viewmodel/
    colorViewModel.js       — состояние + координация: команды, подписка, предупреждения,
                              hex-стопы градиентов (не знает про DOM)
  app.js                    — связывание: события View → команды ViewModel,
                              ViewModel.subscribe → View.render
tests/
  colorMath.test.js         — канонические тесты математики (node:test)
  colorViewModel.test.js    — юнит-тесты ViewModel без DOM
package.json
```

### Поток данных

```
Событие DOM (input / ползунок / палитра / select)
  → колбэк View (парсинг, границы из data-атрибутов)
  → команда ViewModel (setComponent / setHex / setIlluminant / setGamut)
  → пересчет зависимых моделей через colorMath
  → notify подписчиков снапшотом {rgb, xyz, lab, hex, warning, origin, config, gradients}
  → View.render(snapshot)
```

- **Model** (`colorMath.js`) — только вычисления: `rgbToXyz`, `xyzToRgb`, `xyzToLab`,
  `labToXyz`, `buildMatrices`, `getWhitePoint`, `rgbToHex`, `hexToRgb`, `applyGamut`, `clamp`.
  Ни одного обращения к DOM/window — файл исполняется и в браузере, и в Node.
- **ViewModel** (`colorViewModel.js`) — хранит `state {rgb, xyz, lab}`, `config {illuminant, gamut}`,
  `origin` (модель-источник последнего редактирования). Команды клампят значения по границам,
  пересчитывают цепочки и формируют тексты предупреждений. Градиенты ползунков считаются здесь
  (hex-стопы), CSS-строку `linear-gradient(...)` собирает View.
- **View** (`colorView.js`) — находит элементы, навешивает слушатели через `on*`-методы с
  колбэками и отрисовывает снапшот. Не хранит состояние и не считает математику.
  Значение поля ввода, находящегося в фокусе, не перезаписывается при рендере.
- **app.js** — композиция: связывает события View с командами ViewModel и подписывает
  `View.render` на снапшоты.

## Формулы

### Гамма-коррекция sRGB

Линеризация (RGB 0…255 → линейный RGB 0…1):

```
c = C / 255
c_lin = c <= 0.04045 ? c / 12.92 : ((c + 0.055) / 1.055)^2.4
```

Обратное кодирование:

```
c = c_lin <= 0.0031308 ? 12.92 * c_lin : 1.055 * c_lin^(1/2.4) − 0.055
C = 255 * c
```

### Матрица RGB ↔ XYZ

Матрица не берется из справочника, а вычисляется заново из координат цветности
первичных цветов sRGB и белой точки выбранного источника:

1. Каждая первичная (x, y) переводится в XYZ при единичной яркости:
   `X = x / Y₀`, `Z = (1 − x − y) / y` (при `Y = 1`).
2. Составляется матрица `P` из столбцов XYZ первичных.
3. Решается система `P · s = W`, где `W` — белая точка источника (XYZ при Y = 100,
   затем нормированная к 1): `s = P⁻¹ · W`.
4. `M(RGB→XYZ) = P · diag(s)`; обратный переход — через `M⁻¹` (алгебраическое дополнение,
   деленное на определитель).

Для D65 получается стандартная матрица sRGB (допуск 2e-4):

```
[[0.4123908, 0.3575843, 0.1804808],
 [0.2126390, 0.7151687, 0.0721923],
 [0.0193308, 0.1191948, 0.9505322]]
```

Результат умножается на 100, так что XYZ измеряется в диапазоне 0…100.

### XYZ ↔ CIELAB

Белая точка `Xₙ, Yₙ, Zₙ` берется у выбранного источника (для D65 ≈ (95.05, 100, 108.91)).
Функция с порогом δ = 6/29:

```
f(t) = t > δ³ ? t^(1/3) : t / (3δ²) + 4/29
f⁻¹(t) = t > δ ? t³ : 3δ² · (t − 4/29)
```

Прямой переход:

```
L* = 116 · f(Y / Yₙ) − 16
a* = 500 · (f(X / Xₙ) − f(Y / Yₙ))
b* = 200 · (f(Y / Yₙ) − f(Z / Zₙ))
```

Обратный — через `f⁻¹`:

```
fy = (L* + 16) / 116,  fx = fy + a*/500,  fz = fy − b*/200
X = Xₙ · f⁻¹(fx),  Y = Yₙ · f⁻¹(fy),  Z = Zₙ · f⁻¹(fz)
```

### Выход за охват sRGB

Если после `XYZ → RGB` компонента вышла за 0…255 (или стала NaN/∞):

- **Clipping** — каждая компонента ограничивается диапазоном 0…255 независимо.
- **Scaling** — весь расширенный диапазон `[min(0, minRaw), max(255, maxRaw)]`
  пропорционально сжимается в 0…255 (пропорции сохраняются).

## Запуск

Локально (требуется HTTP-сервер — ES-модули не загружаются с `file://`):

```bash
npm run dev
# → http://localhost:8000
```

Тесты (Node.js ≥ 18, встроенный `node:test`, зависимостей нет):

```bash
npm test
```

## Публикация на GitHub Pages

1. Запушить репозиторий на GitHub.
2. Settings → Pages → Source: ветка `main`, папка `/ (root)` → Save.
3. Приложение доступно по адресу `https://<логин>.github.io/<репозиторий>/`.
4. CI (`.github/workflows/tests.yml`) прогоняет `npm test` на каждый push/PR.

Допуски: XYZ 0.02, LAB 0.02, белый/черный — 1e-6…1e-9, матрица — 2e-4.

### Что проверяется

`tests/colorMath.test.js`:

1. Матрица D65 совпадает с эталонной; `toXyz · fromXyz = E`.
2. Эталонная таблица: RGB → XYZ и RGB → LAB для 5 цветов.
3. Обратные переходы: XYZ(41.24, 21.26, 1.93) → RGB ≈ (255, 0, 0); Lab(53.24, 80.09, 67.20) → XYZ.
4. Round-trip на сетке с шагом 51 (125 цветов): RGB → XYZ → RGB — 1e-6; XYZ → LAB → XYZ — 1e-9.
5. Выход за охват: XYZ(0, 100, 0) → `overflow = true`; clipping/scaling дают 0…255,
   scaling сохраняет пропорции (проверяется по `raw`).
6. Белая точка E = (100, 100, 100); матрицы D50 ≠ D65; неизвестный источник — исключение.
7. `hexToRgb`/`rgbToHex`: round-trip и клампинг; `clamp`.

`tests/colorViewModel.test.js` (без DOM):

- `setHex("#ff0000")` → LAB ≈ (53.24, 80.09, 67.20), `origin = "rgb"`.
- `setComponent("xyz", "x", 0)` при Y = 100 → предупреждение о выходе за охват, RGB в границах.
- `setComponent` вне bounds → клампинг + предупреждение о диапазоне.
- `setIlluminant("D50")` → RGB не изменился, X белого ≈ 96.42.
- `setGamut("scaling")` → пересчет от origin, предупреждение сброшено.
- `subscribe`/отписка, `refresh`, градиенты ползунков.
