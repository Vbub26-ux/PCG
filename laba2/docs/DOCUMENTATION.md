## 1. Схема данных парсеров

Каждый парсер принимает `Uint8Array` — начало файла (и полный размер файла; PCX дополнительно получает хвост) — и возвращает объект единой структуры:

| Поле | Тип | Назначение |
|---|---|---|
| `format` | строка | `'JPEG' \| 'GIF' \| 'TIFF' \| 'BMP' \| 'PNG' \| 'PCX'` |
| `width`, `height` | число | размеры изображения в пикселях |
| `dpiX`, `dpiY` | число \| null | разрешение в точках на дюйм; `null` — формат/файл не хранит |
| `bitDepth` | число | суммарная глубина пикселя в битах (для сортировки) |
| `bitDepthText` | строка | человекочитаемая расшифровка («8 бит × 3 канала», «4 бита/пиксель (палитра)») |
| `compression` | строка | метод сжатия/кодирования |
| `extras` | массив | дополнительные характеристики: `{ name, value, description }`; `value` — строка, число или матрица (массив массивов — таблица 8×8 для JPEG DQT) |

Промежуточный ответ `{ needMoreBytes: true }` означает, что буфер мал и приложение дочитывает файл (см. раздел 8).

Общие формулы перевода единиц разрешения:

| Исходная единица | Формула | Где используется |
|---|---|---|
| пиксели на метр (ppm) | `dpi = ppm × 0,0254` (1 дюйм = 0,0254 м) | BMP, PNG |
| точки на сантиметр (dpcm) | `dpi = dpcm × 2,54` | JFIF (units = 3), Exif и TIFF (ResolutionUnit = 3) |

Результат округляется до целого (`Math.round`).

## 2. JPEG

Спецификации: **ITU-T T.81** (собственно JPEG), **JFIF 1.02**, **Exif 2.3**. Порядок байтов многобайтовых полей — big-endian.

### 2.1. Структура потока

Файл — последовательность сегментов-маркеров: байт `0xFF`, код маркера, затем двухбайтовая длина сегмента (включая её саму). Разбор идёт от маркера SOI до маркера SOS или EOI — дальше начинаются сжатые данные, для характеристик не нужные. Повторные байты `0xFF` (заполнители) и экранированный `0x00` пропускаются.

| Маркер | Код | Содержимое |
|---|---|---|
| SOI | `FFD8` | начало потока; проверяется в `sniff` |
| APP0 | `FFE0` | данные JFIF |
| APP1 | `FFE1` | Exif (начинается с `Exif\0\0`) |
| DQT | `FFDB` | таблицы квантования |
| SOF0…SOF15 | `FFC0`–`FFCF` (кроме C4, C8, CC) | параметры кадра |
| COM | `FFFE` | текстовый комментарий |
| SOS / EOI | `FFDA` / `FFD9` | конец заголовочной части |

### 2.2. Источники обязательных характеристик

| Характеристика | Поле | Смещение в данных сегмента |
|---|---|---|
| Высота, px | SOF: высота кадра Y (u16 BE) | +1 |
| Ширина, px | SOF: `frame width` (u16 BE) | +3 |
| dpi | APP0/JFIF: `units` (u8), `Xdensity` (u16 BE), `Ydensity` (u16 BE) | +7, +8, +10 |
| dpi (если JFIF нет) | APP1/Exif: теги XResolution (0x011A), YResolution (0x011B), ResolutionUnit (0x0128) | внутри TIFF-части Exif |
| Глубина цвета | SOF: `sample precision` (u8) × `Nf` — число компонентов (u8) | +0, +5; `bitDepth = precision × Nf` |
| Сжатие | код SOF: C0/C1 → «DCT, baseline, Huffman»; C2 → «DCT, progressive, Huffman»; прочие → «lossless, Huffman» | код маркера |

Правила dpi: `units = 2` — Xdensity/Ydensity уже в dpi; `units = 3` — точки на сантиметр, dpi = значение × 2,54; `units = 1` — задано только соотношение сторон, dpi не выводится. Приоритет: сначала JFIF, при его отсутствии — Exif (ResolutionUnit = 3 → × 2,54, иначе дюймы).

### 2.3. Exif (APP1)

После `Exif\0\0` (6 байт) лежит полноценный TIFF-заголовок (`II`/`MM`, контрольное 42, смещение IFD0) и IFD0 с 12-байтовыми записями (формат — как в разделе 4). Читаются теги: XResolution (0x011A), YResolution (0x011B), ResolutionUnit (0x0128) — тип RATIONAL/SHORT; Make (0x010F), Model (0x0110) — ASCII.

### 2.4. Дополнительные характеристики

| Характеристика | Откуда | Что это и зачем |
|---|---|---|
| Вариант кодирования | код маркера SOF (SOF0…SOF15) | Схема кодирования JPEG: способ DCT-кодирования (baseline, прогрессивный, без потерь) и тип энтропийного кодера. Определяет совместимость и качество |
| Число компонентов | SOF, поле Nf | 1 — градации серого, 3 — цветное (Y, Cb, Cr), 4 — CMYK |
| Субдискретизация цветоразностных каналов | факторы H×V каждого компонента SOF | Частота дискретизации Cb/Cr относительно Y: чем ниже, тем сильнее сжатие и хуже цветовая точность. Выводится как 4:4:4 / 4:2:2 / 4:2:0 / 4:1:1 или перечнем H×V |
| Комментарий | маркер COM (0xFFFE), текст до нулевого байта | Произвольная строка, встроенная в файл при сохранении |
| Таблица квантования #Tq (8/16 бит) | маркер DQT: байт Pq/Tq (старший полубайт — точность, младший — номер таблицы) и 64 значения | Матрица шагов квантования DCT-коэффициентов — задаёт степень сжатия и качество JPEG. Значения хранятся в зигзаг-порядке; парсер восстанавливает естественный построчный порядок 8×8 таблицей ZIGZAG из приложения A спецификации T.81 и выводит матрицу |
| Камера (Exif) | теги Make (0x010F) и Model (0x0110) | Производитель и модель аппаратуры, создавшей файл |

### 2.5. Особенности разбора

- Если SOF не найден, а буфер исчерпан, — `{ needMoreBytes: true }`; если встретились SOS/EOI без SOF — ошибка «В JPEG не найден маркер SOF».
- Сегмент, обрезанный концом буфера, останавливает разбор — уже собранные данные сохраняются.

## 3. GIF

Спецификация: **GIF89a (CompuServe)**. Порядок байтов — little-endian.

### 3.1. Структура заголовка

| Смещение | Размер | Поле |
|---|---|---|
| 0–5 | 6 | сигнатура: `GIF87a` или `GIF89a` |
| 6–7 | u16 LE | Logical Screen Width |
| 8–9 | u16 LE | Logical Screen Height |
| 10 | 1 | packed: бит 7 — флаг глобальной таблицы цветов (GCT); биты 4–6 — цветовое разрешение (colorRes); биты 0–2 — n, размер GCT = 2^(n+1) цветов |
| 11 | 1 | индекс цвета фона |
| 12 | 1 | Pixel Aspect Ratio: 0 — квадратные пиксели, иначе аспект = (v + 15) / 64 |
| 13… | 3 × 2^(n+1) | глобальная таблица цветов (RGB), если флаг установлен |

Далее — цепочка блоков, которую парсер обходит: `0x3B` — Trailer (конец файла); `0x21 label` — расширение с подблоками данных (подблок: байт длины + данные, нулевая длина — конец цепочки), из `0x21 0xF9` (Graphic Control Extension) берётся индекс прозрачного цвета; `0x2C` — Image Descriptor (10 байт: left, top, width, height u16 LE, packed; бит 7 — локальная таблица цветов), за ним LZW-минимальный код и сжатые данные кадра подблоками.

### 3.2. Источники характеристик

| Характеристика | Откуда | Что это и зачем |
|---|---|---|
| Ширина, высота | LSD, поля 6–9 | Размер логического экрана — всего изображения (или первого кадра анимации) |
| dpi | — | GIF не хранит разрешение; выводится «—» |
| Глубина цвета | `gctFlag ? gctSize + 1 : colorRes + 1` бит | Каждый пиксель GIF — индекс в таблице цветов; глубина = разрядность индекса. `bitDepthText` — «8 бит/пиксель (индекс палитры)» |
| Сжатие | константа формата | LZW — словарное сжатие без потерь |

### 3.3. Дополнительные характеристики

| Характеристика | Откуда | Что это и зачем |
|---|---|---|
| Версия GIF | байты 3–5 сигнатуры | 87a — базовый набор возможностей; 89a — анимация, прозрачность, текстовые метки, комментарии |
| Число цветов глобальной палитры | `2^(n+1)` из packed-байта LSD | Размер GCT — сколько цветов доступно всем кадрам файла |
| Число кадров | счётчик блоков Image Descriptor (0x2C) | Больше одного — анимированный GIF |
| Прозрачный цвет | Graphic Control Extension: бит 0 packed-байта + последний байт 4-байтового подблока | Индекс палитры, не отображаемый на фоне (прозрачность 89a) |
| Соотношение сторон пикселя | байт 12 LSD | 0 — квадратные пиксели; иначе коэффициент (v + 15)/64 — нужен для корректного отображения без искажений |

## 4. TIFF

Спецификация: **TIFF 6.0 (Adobe/Aldus)**. Порядок байтов задаётся заголовком и может быть любым.

### 4.1. Структура

| Смещение | Размер | Поле |
|---|---|---|
| 0–1 | 2 | `II` (0x49 0x49) — little-endian или `MM` (0x4D 0x4D) — big-endian |
| 2–3 | u16 | контрольное число 42 |
| 4–7 | u32 | смещение первой IFD (Image File Directory) от начала файла |

IFD: u16 — число записей; затем записи по 12 байт; после записей u32 `nextIFD` — смещение следующей IFD (0 — конец цепочки). Запись:

| Смещение | Размер | Поле |
|---|---|---|
| +0 | u16 | код тега |
| +2 | u16 | тип: 1 = BYTE, 2 = ASCII, 3 = SHORT, 4 = LONG, 5 = RATIONAL (два u32: числитель/знаменатель) |
| +4 | u32 | число значений (count) |
| +8 | 4 | значение, если занимает ≤ 4 байт; иначе смещение значения от начала файла |

### 4.2. Используемые теги

| Тег | Код | Тип | Назначение |
|---|---|---|---|
| ImageWidth | 256 (0x0100) | SHORT/LONG | ширина, px |
| ImageLength | 257 (0x0101) | SHORT/LONG | высота, px |
| ImageDescription | 270 (0x010E) | ASCII | описание изображения |
| Make | 271 (0x010F) | ASCII | производитель аппаратуры |
| Model | 272 (0x0110) | ASCII | модель устройства |
| BitsPerSample | 258 (0x0102) | SHORT | бит на канал; `bitDepth` = сумма значений |
| Compression | 259 (0x0103) | SHORT | метод сжатия |
| PhotometricInterpretation | 262 (0x0106) | SHORT | цветовая модель |
| SamplesPerPixel | 277 (0x0115) | SHORT | число каналов (по умолчанию 1) |
| XResolution | 282 (0x011A) | RATIONAL | разрешение по X |
| YResolution | 283 (0x011B) | RATIONAL | разрешение по Y |
| PlanarConfiguration | 284 (0x011C) | SHORT | порядок хранения каналов |
| ResolutionUnit | 296 (0x0128) | SHORT | 1 — не задано, 2 — дюйм (по умолчанию), 3 — сантиметр |
| Software | 305 (0x0131) | ASCII | программа-создатель |
| DateTime | 306 (0x0132) | ASCII | дата создания «ГГГГ:ММ:ДД ЧЧ:ММ:СС» |

### 4.3. Источники обязательных характеристик

| Характеристика | Правило |
|---|---|
| Размеры | теги ImageWidth/ImageLength; отсутствие — ошибка |
| dpi | XResolution и YResolution (RATIONAL, уже поделённая дробь num/den); при ResolutionUnit = 3 умножаются на 2,54 (dpcm → dpi); при unit = 1 не вычисляются |
| Глубина цвета | сумма значений BitsPerSample; при отсутствии тега — по 1 биту на каждый SamplesPerPixel. Пример текста: «8 бит × 3 канала» либо «8+8+8 бит × 3 канала» при разных значениях |
| Сжатие | тег Compression (по умолчанию 1): 1 — без сжатия, 2 — CCITT RLE, 3/4 — CCITT Group 3/4, 5 — LZW, 6/7 — JPEG, 8 — Deflate (Adobe), 32773 — PackBits, 32909 — Deflate, 34712 — JPEG 2000; неизвестный код выводится как «код N» |

### 4.4. Дополнительные характеристики

Число каналов (SamplesPerPixel); цветовая модель (PhotometricInterpretation: WhiteIsZero/BlackIsZero/RGB/палитра/маска/CMYK/YCbCr); порядок хранения каналов (PlanarConfiguration: chunky — все каналы пикселя вместе, planar — каналы отдельными плоскостями); порядок байт (II/MM); число страниц — обход цепочки nextIFD от первой IFD (с защитой от циклов); производитель; модель; программа; дата; описание изображения.

### 4.5. Особенности разбора

Если значение тега лежит за пределами переданного буфера, но внутри файла, парсер возвращает `{ needMoreBytes: true }` — приложение дочитывает файл (см. 8.3). Значения за пределами файла считаются повреждением и пропускаются.

## 5. BMP / DIB

Спецификация: **Microsoft DIB**. Порядок байтов — little-endian.

### 5.1. BITMAPFILEHEADER (14 байт)

| Смещение | Размер | Поле |
|---|---|---|
| 0–1 | 2 | сигнатура `BM` (0x4D42 LE) |
| 2–5 | u32 | bfSize — размер файла (читается справочно) |
| 6–9 | 4 | зарезервировано |
| 10–13 | u32 | bfOffBits — смещение пиксельных данных |

### 5.2. DIB-заголовок

Версия определяется полем размера DIB-заголовка (u32 по смещению 14):

| Размер | Версия | Особенности |
|---|---|---|
| 12 | BITMAPCOREHEADER (OS/2, Windows 1.x) | размеры — u16, полей сжатия и разрешения нет |
| 40 | BITMAPINFOHEADER (Windows 3.x) | базовый современный вариант |
| 108 | BITMAPV4HEADER | + цветовые профили |
| 124 | BITMAPV5HEADER | + ICC-профиль |

Поля BITMAPINFOHEADER и старше (смещения от начала файла):

| Смещение | Размер | Поле |
|---|---|---|
| 18–21 | s32 | biWidth — ширина, px |
| 22–25 | s32 | biHeight — высота, px (отрицательная — строки сверху вниз, берётся модуль) |
| 26–27 | u16 | biPlanes — число плоскостей (всегда 1) |
| 28–29 | u16 | biBitCount — бит на пиксель |
| 30–33 | u32 | biCompression — метод сжатия |
| 34–37 | s32 | biSizeImage — размер данных изображения |
| 38–41 | s32 | biXPelsPerMeter — пиксели на метр по X |
| 42–45 | s32 | biYPelsPerMeter — пиксели на метр по Y |
| 46–49 | u32 | biClrUsed — цветов в палитре |
| 50–53 | u32 | biClrImportant — значимых цветов |

В BITMAPCOREHEADER: ширина u16 (18–19), высота u16 (20–21), плоскости (22–23), бит на пиксель (24–25); сжатие — всегда BI_RGB, разрешение не задаётся.

### 5.3. Источники обязательных характеристик

| Характеристика | Правило |
|---|---|
| Размеры | biWidth / biHeight (|модуль|); CORE — u16-поля |
| dpi | `biXPelsPerMeter / biYPelsPerMeter × 0,0254` (ppm → dpi); нулевое или отрицательное поле — «—» |
| Глубина цвета | biBitCount; при ≤ 8 бит — палитровый формат |
| Сжатие | biCompression: 0 — BI_RGB (без сжатия), 1 — BI_RLE8, 2 — BI_RLE4, 3 — BI_BITFIELDS, 4 — JPEG, 5 — PNG, 6 — BI_BITFIELDS (HALF) |

### 5.4. Дополнительные характеристики

Версия заголовка (по полю размера — CORE/INFO/V4/V5); число цветовых плоскостей (biPlanes); число цветов палитры — явное biClrUsed, иначе 2^biBitCount при глубине ≤ 8 бит, при большей глубине палитры нет.

## 6. PNG

Спецификация: **W3C PNG (ISO/IEC 15948)**. Порядок байтов — big-endian.

### 6.1. Структура

Сигнатура: 8 байт `89 50 4E 47 0D 0A 1A 0A`. Далее цепочка чанков: u32 BE длина данных, 4 байта тип (ASCII), данные, u32 BE CRC (пропускается). Обход идёт до IEND или конца буфера.

### 6.2. Чанк IHDR — обязательный первый

Данные чанка — 13 байт, начинаются со смещения 16 файла:

| Смещение (от начала файла) | Размер | Поле |
|---|---|---|
| 16–19 | u32 BE | Width — ширина, px |
| 20–23 | u32 BE | Height — высота, px |
| 24 | u8 | Bit Depth — бит на канал: 1/2/4/8/16 |
| 25 | u8 | Color Type: 0 — Grayscale (1 канал), 2 — Truecolor RGB (3), 3 — Indexed (1), 4 — Grayscale+Alpha (2), 6 — RGBA (4) |
| 26 | u8 | метод сжатия (0 = Deflate; иное — ошибка) |
| 27 | u8 | метод фильтрации (0; иное — ошибка) |
| 28 | u8 | интерлейс: 0 — нет, 1 — Adam7 |

### 6.3. Прочие разбираемые чанки

| Чанк | Структура | Использование |
|---|---|---|
| pHYs | ppux u32 BE, ppuy u32 BE, unit u8 | при unit = 1 (пиксели на метр): dpi = ppm × 0,0254; иначе плотность без единицы — не выводится |
| PLTE | тройки RGB | число цветов = длина данных / 3 (для типа цвета Indexed) |

### 6.4. Источники обязательных характеристик

| Характеристика | Правило |
|---|---|
| Размеры | IHDR: Width, Height |
| dpi | pHYs (формула ppm × 0,0254, округление до целого) |
| Глубина цвета | для Indexed — бит на индекс; иначе бит на канал × число каналов типа цвета (например 8 × 3 = 24) |
| Сжатие | Deflate (zlib), без потерь — единственный метод PNG |

### 6.5. Дополнительные характеристики

Тип цвета (код + расшифровка, определяет состав каналов); интерлейс Adam7 (семь проходов от грубого к детальному — картинка проявляется при медленной загрузке); число бит на канал; число цветов палитры (PLTE).

## 7. PCX

Спецификация: **ZSoft PCX 1.0/3.0** (Paintbrush). Порядок байтов — little-endian.

### 7.1. Заголовок — всегда 128 байт

| Смещение | Размер | Поле |
|---|---|---|
| 0 | u8 | Manufacturer — магическое число 10 (0x0A) |
| 1 | u8 | Version: 0 — 2.5 (без палитры, EGA); 1 — не документирована; 2 — 2.8 с палитрой (EGA); 3 — 2.8 без палитры; 4 — Paintbrush for Windows; 5 — 3.0 и выше (VGA) |
| 2 | u8 | Encoding: 1 — RLE, 0 — без сжатия |
| 3 | u8 | BitsPerPixel — бит **на плоскость** (1/2/4/8) |
| 4–5 | u16 LE | Xmin |
| 6–7 | u16 LE | Ymin |
| 8–9 | u16 LE | Xmax |
| 10–11 | u16 LE | Ymax |
| 12–13 | u16 LE | HDPI — точки на дюйм по горизонтали |
| 14–15 | u16 LE | VDPI — точки на дюйм по вертикали |
| 16–63 | 48 | EGA-палитра: 16 цветов × 3 байта RGB |
| 64 | u8 | Reserved |
| 65 | u8 | NPlanes — число цветовых плоскостей (1/2/3/4) |
| 66–67 | u16 LE | BytesPerLine — байт на строку развёртки одной плоскости (с выравниванием) |
| 68–69 | u16 LE | PaletteType: 1 — цветная, 2 — градации серого |
| 70–71 | u16 LE | HScreenSize |
| 72–73 | u16 LE | VScreenSize |
| 74–127 | 54 | Filler |

### 7.2. VGA-палитра в конце файла

У 8-битных PCX (bitsPerPixel = 8, nPlanes = 1, version ≥ 5) палитра из 256 цветов (768 байт RGB) хранится в **конце** файла; за 769 байт до конца расположен байт-идентификатор `0x0C`. Для его проверки приложение отдельно дочитывает последние 1024 байта файла (см. 8.3).

### 7.3. Источники обязательных характеристик

| Характеристика | Правило |
|---|---|
| Размеры | `width = Xmax − Xmin + 1`, `height = Ymax − Ymin + 1`; некорректные границы — ошибка |
| dpi | поля HDPI/VDPI напрямую (формат хранит сразу точки на дюйм, пересчёт не нужен) |
| Глубина цвета | `bitDepth = BitsPerPixel × NPlanes`; текст: «8 бит/пиксель» или «1 бит × 4 плоскости» |
| Сжатие | Encoding: 1 — RLE (кодирование длин серий), 0 — без сжатия |

### 7.4. Дополнительные характеристики

Версия PCX; число плоскостей (1 — палитровый цвет, 3 — RGB, 4 — RGB + интенсивность); байт на строку развёртки — по нему RLE-декодер находит границы строк; тип палитры (цветная/серая); наличие VGA-палитры 256 цветов (маркер 0x0C в хвосте); EGA-палитра 16 цветов в заголовке.

## 8. Архитектура приложения

### 8.1. Глобальное пространство ImgInfo

Скрипты подключаются тегами `<script>` без модулей и сборки. Каждый файл — IIFE, регистрирующий функции в глобальном объекте `ImgInfo` (`js/parser.js`, все `js/formats/*.js`):

- `ImgInfo.extensions` — карта расширений → ключ формата (`jpg/jpeg/jfif → jpeg`, `gif → gif`, `tif/tiff → tiff`, `bmp/dib → bmp`, `png → png`, `pcx → pcx`);
- `ImgInfo.jpeg / .gif / .tiff / .bmp / .png / .pcx` — парсеры форматов;
- `ImgInfo.sniff(bytes)` — определение формата по сигнатуре;
- `ImgInfo.parse(bytes, ext, fileSize, tailBytes)` — диспетчер.

В среде Node те же файлы подключаются к `globalThis` — на этом построены тесты (раздел 9).

### 8.2. Определение формата (sniff)

| Сигнатура | Формат |
|---|---|
| `FF D8` | JPEG |
| `GIF8` | GIF |
| `II 2A 00` или `MM 00 2A` | TIFF |
| `BM` | BMP |
| `89 50 4E 47` | PNG |
| `0A`, второй байт ≤ 5 (версия), байт 65 < 10 (sanity-проверка nPlanes) | PCX |

`parse` сначала верит сигнатуре; если она не опознана — расширению файла; иначе «Формат файла не поддерживается». Для PCX парсеру дополнительно передаётся хвост файла.

### 8.3. Каскад дочитки (needMoreBytes)

Константы `js/app.js`: `READ_LIMITS = [131072, 524288, 2097152]` (128 КБ → 512 КБ → 2 МБ), `PCX_TAIL_BYTES = 1024`.

Схема `parseRow(row)`:

1. читаются первые `min(размер файла, 128 КБ)` (`file.slice(0, limit)` → `Uint8Array`);
2. вызывается парсер; ошибка — строка получает статус `error` с сообщением;
3. ответ `{ needMoreBytes: true }` — файл перечитывается следующей ступенью каскада (512 КБ, затем 2 МБ); последняя ступень безуспешна — «заголовок не прочитан»;
4. результат формата PCX — дочитывается хвост (последние 1024 байта) для поиска VGA-палитры, разбор повторяется с ним.

`needMoreBytes` возвращают JPEG (SOF за пределами буфера) и TIFF (значения тегов за пределами буфера). Типичный файл укладывается в первую ступень.

### 8.4. Пул параллелизма

`PARALLELISM = 32`: запускается до 32 «воркеров»-корутин, каждая атомарно забирает следующий индекс из общего счётчика (`nextIndex`) и обрабатывает файл (`await parseRow`). После обработки ссылка на `File` из строки освобождается (`row.file = null`). Прогресс-бар и счётчик обновляются не чаще чем раз в 100 мс (`PROGRESS_STEP_MS`). Токен `runToken` отменяет отрисовку устаревшего прогона при повторном выборе папки.

### 8.5. Таблица, фильтры, пагинация

- строки: `ok` / `error` / `skipped` (неподдерживаемое расширение);
- фильтры-чипы: все / по формату / ошибки / пропущенные; поиск по подстроке имени с debounce 200 мс;
- сортировка щелчком по заголовку столбца: имя (localeCompare «ru»), формат, ширина, высота, dpi (по dpiX), глубина, размер файла; повторный щелчок меняет направление;
- пагинация `PAGE_SIZE = 500`: в DOM держится только текущая страница — таблица остаётся быстрой даже на 100 000 строк;
- панель подробностей (drawer) по клику на строку: обязательные характеристики, сведения о файле и все `extras` — значения-матрицы (таблицы квантования) рендерятся таблицами 8×8;
- экспорт CSV: столбцы №; имя; формат; ширина; высота; DPI X; DPI Y; глубина; сжатие; доп. характеристики; размер в байтах; разделитель «;», BOM UTF-8, экранирование кавычек; имя файла `images-info.csv`.

### 8.6. Лимиты

`MAX_FILES = 100000` — верхняя граница выбора папки; лишние файлы отбрасываются.

## 9. Тестирование

Тестовый контур — два скрипта Node без зависимостей (файлы парсеров подключаются к `globalThis`, как описано в 8.1).

**`tools/generate-test-images.mjs`** — генератор тестовых данных: создаёт набор файлов всех шести форматов с известными наперёд характеристиками — размеры, dpi (включая случаи dpcm/ppm, требующие пересчёта), глубина цвета, сжатие и дополнительные структуры (таблицы квантования JPEG, палитры GIF/PNG/PCX, Exif-теги, IFD-теги TIFF, версии DIB-заголовков BMP).

**`tests/test-parsers.mjs`** — читает сгенерированные файлы, прогоняет их через `ImgInfo.parse` и сверяет каждое поле результата (`format`, `width`, `height`, `dpiX`, `dpiY`, `bitDepth`, `compression`, состав `extras`) с ожидаемым значением. При расхождении выводит список несовпадений и завершается ненулевым кодом.

Запуск:

```bash
node tools/generate-test-images.mjs
node tests/test-parsers.mjs
```

## 10. Ограничения

- **GIF не хранит разрешение** — в столбце dpi всегда «—» (свойство формата).
- TIFF: читаются теги только типов BYTE/ASCII/SHORT/LONG/RATIONAL (прочие пропускаются); значения за пределами файла считаются повреждением; неизвестные схемы сжатия выводятся как «код N»; нестандартные реализации формата могут не поддерживаться.
- JPEG: файл без маркера SOF — ошибка; из Exif берётся только базовый набор тегов (разрешение, камера).
- BMP: неизвестный размер DIB-заголовка — ошибка; BITMAPCOREHEADER не содержит полей сжатия и разрешения (сжатие — BI_RGB, dpi — «—»).
- PNG: pHYs без единицы измерения (unit ≠ 1) не переводится в dpi.
- PCX: поддерживаются версии 0–5; VGA-палитра признаётся только при маркере 0x0C в хвосте 8-битного файла.
- Приложение читает метаданные заголовков и не декодирует пиксельные данные изображений.
