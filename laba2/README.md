# Лабораторная работа 2. Чтение информации из графических файлов

Веб-приложение на чистом HTML/CSS/JavaScript (без внешних библиотек и сборщиков), которое читает основную информацию об изображениях **JPG, GIF, TIFF, BMP, PNG и PCX** из выбранной пользователем папки (до 100 000 файлов) и выводит её в таблицу. Все характеристики извлекаются самописным разбором бинарных заголовков файлов по официальным спецификациям форматов — само изображение не декодируется.

Оценивание: **80 баллов**.

## Цель работы

Разработать клиентское веб-приложение, которое для выбранной папки (или отдельных файлов) с графическими файлами определяет и выводит в виде таблицы основную информацию о каждом изображении: имя файла, размер в пикселях, разрешение (dpi), глубину цвета, метод сжатия, — а также дополнительные характеристики формата (таблицы квантования JPEG, палитры GIF и т. п.), каждая с пояснением «что это и зачем». Данные должны извлекаться самостоятельно, без использования сторонних библиотек; приложение выкладывается в общий доступ как статический сайт.

## Что делает

### Обязательные характеристики (для каждого файла)

- **имя файла** (и относительный путь внутри выбранной папки);
- **размер в пикселях** — ширина × высота;
- **разрешение** — dpi по горизонтали и вертикали;
- **глубина цвета** — бит на пиксель (с расшифровкой: бит × каналы);
- **сжатие** — метод сжатия/кодирования;
- дополнительно: формат и размер файла в байтах.

### Дополнительные характеристики по форматам

Открываются кликом по строке таблицы в панели подробностей; каждая снабжена пояснением.

| Формат | Дополнительные характеристики |
|---|---|
| **JPEG** | вариант кодирования (SOF0…SOF15); число компонентов; субдискретизация цветоразностных каналов (4:4:4, 4:2:2, 4:2:0…); комментарий (маркер COM); таблицы квантования DQT — матрицы 8×8 с восстановлением естественного порядка из зигзаг-порядка; камера (Exif: Make/Model) |
| **GIF** | версия (87a/89a); число цветов глобальной палитры (GCT); число кадров — признак анимации; индекс прозрачного цвета (Graphic Control Extension); соотношение сторон пикселя |
| **TIFF** | число каналов (SamplesPerPixel); цветовая модель (PhotometricInterpretation); порядок хранения каналов (chunky/planar); порядок байт (II/MM); число страниц (обход цепочки IFD); производитель, модель, программа, дата, описание изображения |
| **BMP** | версия DIB-заголовка (BITMAPCORE/INFO/V4/V5); число цветовых плоскостей; число цветов палитры (biClrUsed) |
| **PNG** | тип цвета (Grayscale/RGB/Indexed/Gray+Alpha/RGBA); интерлейс Adam7; число бит на канал; число цветов палитры (чанк PLTE) |
| **PCX** | версия формата (2.5…3.0); число плоскостей; байт на строку развёртки (bytesPerLine); тип палитры (цветная/серая); наличие VGA-палитры 256 цветов в конце файла; EGA-палитра 16 цветов в заголовке |

### Интерфейс

- выбор папки или отдельных файлов, drag&drop папки/файлов на страницу;
- сводная статистика: всего файлов, успешно, ошибок, пропущено, время обработки, распределение по форматам;
- таблица с сортировкой по столбцам, поиском по имени, фильтрами-чипами по форматам и пагинацией;
- панель подробностей по клику на строку;
- экспорт таблицы в CSV (UTF-8, разделитель «;»);
- встроенная справка «откуда берётся каждая характеристика».

## Как запустить

### Вариант А — двойной клик (без сервера)

Открыть `index.html` двойным кликом. Приложение полностью клиентское и работает с протоколом `file://`. Для выбора целой папки нужен браузер с поддержкой атрибута `webkitdirectory` — рекомендуется **Chrome** или **Edge** (drag&drop папки работает и в других браузерах).

### Вариант Б — локальный сервер

```bash
cd laba2
python3 -m http.server 8000
```

Открыть http://localhost:8000.

### Вариант В — статический хостинг (общий доступ)

Папка проекта — обычный статический сайт без сборки: достаточно выложить её содержимое на любой статический хостинг (GitHub Pages, Netlify, GitLab Pages и т. п.). Это выполняет требование задания «веб-приложение, выложенное в общий доступ»: любой пользователь по ссылке может открыть приложение и загрузить свои файлы — они обрабатываются локально в его браузере и никуда не отправляются.

## Каким способом доставали данные

**Никакие внешние библиотеки не использовались.** Все характеристики вычисляются собственным кодом на JavaScript: файл читается в `Uint8Array`, и парсер вручную разбирает бинарные заголовки по официальным спецификациям форматов (смещения полей, порядок байт, битовые маски, обход структур переменной длины — маркеры JPEG, теги TIFF, чанки PNG, блоки GIF). Сторонние парсеры, полифиллы и npm-пакеты отсутствуют; зависимостей нет вообще.

| Формат | Спецификация | Ключевые разбираемые структуры | Откуда обязательные поля |
|---|---|---|---|
| JPEG/JFIF | ITU-T T.81, JFIF 1.02, Exif 2.3 | поток маркеров: SOF, APP0 (JFIF), APP1 (Exif), DQT, COM | размеры — SOF; dpi — X/Ydensity из APP0 либо X/YResolution из Exif; глубина — точность × число компонентов (SOF); сжатие — код SOF |
| GIF | GIF89a (CompuServe) | сигнатура, Logical Screen Descriptor, глобальная таблица цветов, обход блоков расширений и Image Descriptor | размеры — LSD; dpi — формат не хранит («—»); глубина — разрядность индекса палитры; сжатие — LZW |
| TIFF | TIFF 6.0 (Adobe) | заголовок порядка байт, цепочка IFD с 12-байтовыми тегами (типы BYTE/ASCII/SHORT/LONG/RATIONAL) | размеры — теги 256/257; dpi — теги 282/283 + 296; глубина — сумма тега 258; сжатие — тег 259 |
| BMP/DIB | Microsoft DIB | BITMAPFILEHEADER + DIB-заголовок (BITMAPCORE/INFO/V4/V5) | размеры — biWidth/biHeight; dpi — biX/Y PelsPerMeter × 0,0254; глубина — biBitCount; сжатие — biCompression |
| PNG | W3C PNG (ISO/IEC 15948) | сигнатура, чанки IHDR, pHYs, PLTE | размеры — IHDR; dpi — pHYs (пиксели на метр × 0,0254); глубина — бит на канал × каналы (colorType); сжатие — Deflate |
| PCX | ZSoft PCX 1.0/3.0 | 128-байтный заголовок, VGA-палитра в конце файла | размеры — xmax−xmin+1 / ymax−ymin+1; dpi — поля hDPI/vDPI; глубина — бит на плоскость × плоскости; сжатие — поле encoding (RLE) |

Формула перевода единиц разрешения: **пиксели/метр × 0,0254 = dpi** (PNG, BMP); **точки/см × 2,54 = dpi** (JFIF/Exif/TIFF при ResolutionUnit = 3).

## Быстродействие

Папка из ~600 JPEG общим объёмом ~2 ГБ обрабатывается за секунды. Причины:

1. **Читаются только заголовочные байты, а не весь файл.** Первый запрос — 128 КБ файла; почти всегда этого достаточно (типичный заголовок JPEG — единицы килобайт).
2. **Каскад дочитки 128 КБ → 512 КБ → 2 МБ** включается только если парсер ответил `needMoreBytes` (например, у JPEG с очень большим Exif или у TIFF с далеко лежащими значениями тегов).
3. **Пул на 32 параллельных чтения** — файлы обрабатываются конкурентно, не по очереди.
4. **Пагинация таблицы** (по 500 строк) — DOM не раздувается тысячами строк даже при 100 000 файлов; поиск и перерисовка остаются отзывчивыми.
5. Прогресс обновляется не чаще 10 раз в секунду, поиск debounce'ится — интерфейс не тормозит во время обработки.

```
laba2/
├── index.html                    — разметка: панель управления, таблица, пагинация,
│                                   панель подробностей, модальное окно справки
├── css/
│   └── style.css                 — стили интерфейса (без фреймворков)
├── js/
│   ├── parser.js                 — диспетчер: определение формата по сигнатуре (sniff),
│   │                               вызов парсера нужного формата из ImgInfo
│   ├── app.js                    — логика приложения: выбор/перетаскивание файлов,
│   │                               каскадное чтение заголовков, пул параллелизма,
│   │                               таблица, фильтры, сортировка, пагинация, CSV
│   └── formats/
│       ├── jpeg.js               — парсер JPEG (ITU-T T.81, JFIF, Exif, DQT)
│       ├── gif.js                — парсер GIF (GIF87a/89a, LSD, обход блоков)
│       ├── tiff.js               — парсер TIFF 6.0 (IFD-теги, оба порядка байт)
│       ├── bmp.js                — парсер BMP/DIB (CORE/INFO/V4/V5)
│       ├── png.js                — парсер PNG (IHDR/pHYs/PLTE)
│       └── pcx.js                — парсер PCX (заголовок 128 байт + хвост-палитра)
├── tools/
│   └── generate-test-images.mjs  — генератор тестовых изображений всех форматов (Node)
├── tests/
│   └── test-parsers.mjs          — тесты парсеров (Node, без зависимостей)
├── docs/
│   └── DOCUMENTATION.md          — техническая справка: форматы, поля, архитектура
└── README.md                     — этот файл
```

Подключение скриптов — обычными тегами `<script>` в `index.html`; каждый парсер оформлен как IIFE и регистрирует себя в глобальном пространстве имён `ImgInfo`.

## Тесты

Требуется установленный Node.js (зависимостей у тестов нет).

```bash
node tools/generate-test-images.mjs   # сгенерировать набор тестовых изображений
node tests/test-parsers.mjs           # проверить парсеры на сгенерированных файлах
```

Генератор создаёт изображения всех шести поддерживаемых форматов с заранее известными характеристиками (размеры, dpi, глубина цвета, сжатие, доп. данные). Тест читает те же файлы парсерами из `js/formats/` в среде Node и сверяет каждое поле с ожидаемым значением; при расхождении выводит перечень несовпадений и ненулевой код выхода.

## Поддерживаемые форматы и источники данных

Сводка — где берётся каждая обязательная характеристика (подробный разбор со смещениями полей — в [docs/DOCUMENTATION.md](docs/DOCUMENTATION.md)).

| Формат | Расширения | Размер, px | Разрешение, dpi | Глубина цвета | Сжатие |
|---|---|---|---|---|---|
| JPEG | .jpg, .jpeg, .jfif | маркер SOF: height, width | APP0/JFIF: units + Xdensity/Ydensity; иначе APP1/Exif: теги XResolution/YResolution + ResolutionUnit | точность отсчётов × число компонентов | DCT по коду SOF: baseline / progressive / lossless (Хаффман) |
| GIF | .gif | Logical Screen Descriptor | — (формат не хранит разрешение) | бит на индекс палитры (GCT) | LZW (без потерь) |
| TIFF | .tif, .tiff | теги ImageWidth (256), ImageLength (257) | теги XResolution (282), YResolution (283) + ResolutionUnit (296) | сумма значений тега BitsPerSample (258) | тег Compression (259): без сжатия / LZW / PackBits / Deflate / CCITT… |
| BMP | .bmp, .dib | biWidth, biHeight (модуль — при отрицательной высоте) | biXPelsPerMeter, biYPelsPerMeter × 0,0254 | biBitCount | biCompression: BI_RGB / BI_RLE8 / BI_RLE4 / BI_BITFIELDS… |
| PNG | .png | чанк IHDR: Width, Height | чанк pHYs: пиксели на метр × 0,0254 (при unit = 1) | бит на канал × число каналов по colorType | Deflate (zlib), без потерь |
| PCX | .pcx | xmax − xmin + 1, ymax − ymin + 1 | поля hDPI, vDPI заголовка | бит на плоскость × nPlanes | RLE (поле encoding) или без сжатия |

## Ограничения

- **GIF не хранит разрешение** — в столбце dpi выводится «—» (это свойство формата, а не недоработка).
- Экзотические и нестандартные реализации TIFF могут не поддерживаться: читаются только IFD-теги типов BYTE/ASCII/SHORT/LONG/RATIONAL; значения тегов за пределами файла считаются повреждением; нестандартные схемы сжатия выводятся как «код N».
- JPEG без маркера SOF (повреждённый файл) и BMP с неизвестным размером DIB-заголовка отмечаются как ошибки с пояснением в столбце «Сжатие».
- Приложение читает метаданные, но не декодирует и не отображает сами изображения.
